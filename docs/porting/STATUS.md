# Porting status — anthropic (Python) 2.3.0 → Swift

Everything in the upstream SDK is either generated by the transpiler or ported by hand, with its tests.
`swift test` runs ~3,750 tests (1,574 generated from `tests/api_resources`, the rest hand-ported).
Per-area details, including every upstream test that was skipped and why, are in the files linked below.

## Generated tests not produced by the transpiler

[GENERATED_TESTS_SKIPPED.txt](GENERATED_TESTS_SKIPPED.txt) lists 10 upstream `api_resources` tests whose shape the
test transpiler doesn't handle; each is ported by hand: the batch `results` tests
(`Lib/Streaming/BatchResultsTests.swift`), `test_output_format_conversion` (`Lib/Parse/`), and
`test_deprecated_model_warning` (`Core/DeprecatedModelWarningTests.swift`).

## Deliberate differences

* One async client instead of sync + async twins.
* `X-Stainless-Lang: swift` and a Swift user agent in telemetry headers.
* Responses are decoded strictly into typed models (unknown enum values and union variants are kept via
  `unknown(...)` cases; unknown object keys are dropped). Python's non-strict `construct` leniency for
  missing required fields has no equivalent.
* Structured outputs use a `StructuredOutput` protocol (a `Decodable` type supplying its JSON schema) instead of
  pydantic schema inference; function tools declare their input schema explicitly instead of inferring it from a
  Python signature.
* No third-party dependencies: crypto (SigV4, Google service-account JWTs, webhooks), gzip/zip/tar reading and the
  OpenTelemetry API are implemented in-tree.
